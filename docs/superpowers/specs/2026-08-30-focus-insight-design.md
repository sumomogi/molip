# 집중 기록과 인사이트

작업 세션을 파일에 남기고, 요일 × 시간대로 모아 "언제 가장 잘 집중하는지"를
한 문장으로 알려준다.

## 목적

지금 몰입은 아무것도 기억하지 않는다. 앱을 껐다 켜면 오늘 얼마나 집중했는지
알 길이 없다. 기록을 남기면 그 자체로 쓸모가 있고, 몇 주가 쌓이면 개인의
리듬이 보인다. 그 리듬을 알면 중요한 일을 좋은 시간대에 배치할 수 있다.

## 저장

`~/Library/Application Support/Molip/sessions.jsonl`

한 줄에 한 세션. 추가만 하므로 쓰기가 짧고, 사람이 그대로 열어 읽을 수 있다.

```
{"start":"2026-08-30T15:44:04+09:00","seconds":3000,"completed":true}
{"start":"2026-08-30T17:02:11+09:00","seconds":1620,"completed":false}
```

하루 다섯 세션이면 1년에 약 130KB다. SQLite는 이 양에 과하고, UserDefaults는
계속 자라는 데이터를 담을 곳이 아니다.

`start`는 ISO8601에 **로컬 오프셋을 붙여** 적는다. `JSONEncoder`의 `.iso8601`
전략은 UTC(`Z`)로 적어 오프셋을 잃으므로 쓰지 않는다.

구현에서는 `.current`를 쓰는 시점을 기록 시점으로 한 번 못박아 `Session.offsetSeconds`
필드에 담고, `ISO8601DateFormatter`는 그 값으로 `timeZone`을 만든다(`SessionLog.line(for:)`).
"쓸 때의 `.current`"가 아니라 "그 세션이 담고 있는 오프셋"이라, 나중에 저장된
값을 다시 직렬화해도 지금 기기의 시간대에 휩쓸리지 않는다.

읽을 때는 문자열의 오프셋으로 요일과 시간을 계산한다. 그래야 사용자가 다른
시간대로 이동해도 과거 기록이 다시 쓰이지 않는다. "이번 주" 경계만 현재
시간대를 쓴다.

## 구성

새 파일 셋. 한 파일 한 역할이라는 기존 규칙을 따른다.

| 파일 | 역할 | 의존 |
|---|---|---|
| `SessionLog.swift` | `Session` 타입, 파일 추가·읽기 | Foundation |
| `Insight.swift` | `[Session]` → 히트맵·최적 구간. 순수 함수 | `Session` |
| `HistoryView.swift` | 팝오버 세 번째 화면 | SwiftUI, `Insight` |

`PopoverView.swift`는 이미 267줄이라 화면을 더 붙이지 않는다.

고치는 곳:

| 파일 | 변경 |
|---|---|
| `TimerEngine.swift` | 작업 시작 시각 보관, 세션 종료를 콜백으로 알림 |
| `PopoverView.swift` | 화면 전환을 `Bool` → `enum Screen`, 기록 버튼 |
| `main.swift` | 콜백을 `SessionLog`에 연결, 종료 시 저장 |
| `Strings.swift` | 문자열 추가 |

`TimerEngine`은 파일을 직접 만지지 않는다. `onComplete`와 같은 방식으로
`onWorkSessionEnded`를 내보내고 `AppDelegate`가 받아 적는다. 그래야 엔진이
파일 없이도 테스트된다.

## 기록 지점

작업 단계가 끝나는 경로는 넷뿐이다.

| 시점 | 기록 |
|---|---|
| 작업 완료 (`advance`) | `completed: true` |
| 사용자가 정지 (`stop`) | `completed: false` |
| 앱 종료 (`applicationWillTerminate` → `stop`) | `completed: false` |
| 60초 미만 | 버림 |

길이는 `Date().timeIntervalSince(시작시각)`을 쓰고 단계 전체 길이로 자른다.
맥이 잠들어도 벽시계 기준이라 실제 흐른 시간이 남는다.

휴식은 기록하지 않는다. 인사이트에 쓰지 않으면서 파일만 두 배로 만든다.

맥이 잠들거나 앱이 강제 종료되면 그 세션은 잃는다. 지금 구조로는 막을 수
없으므로 그대로 둔다.

## 인사이트

전부 `Insight`의 순수 함수다. 입력은 `[Session]`과 기준 시각, 출력은 표와 문장.

### 버킷

요일 7 × 3시간대 8칸(`00-03`, `03-06`, … `21-24`). 행 이름은 시작 시각.

한 주 전체가 빈 시간대 행은 감춘다. 새벽에 일하는 사람도 자기 시간대만 보게
되고, 240pt 팝오버가 길어지지 않는다.

### 집계 범위

최근 8주(기준 시각에서 56일). 습관이 바뀌면 화면도 따라 바뀐다.
파일에는 전부 남긴다.

### 농도

칸 합계를 기준값과 견준 비율로 4단계.

> **구현 중 변경.** 여기 원래는 "그 창에서 가장 큰 칸과 견준 비율"이라고 적혀
> 있었다. 실제로 만들어보니 어쩌다 한 번 길게 돌린 세션 하나가 최댓값이 되어
> 나머지 칸을 전부 최저 단계로 눌러버렸다 — 정작 보여줘야 할 반복되는 습관이
> 지워지는 문제였다. 그래서 기준값을 **0이 아닌 칸들을 정렬한 상위 25% 지점**
> (`Insight.reference(of:)`)으로 바꿨다. 이상치 하나에 흔들리지 않는다.

```
비율 0            알파 0.15   (빈 칸도 자리는 보인다)
 0 초과 ~ 2/3 이하    0.35
 2/3 초과 ~ 1.0 미만   0.65
 1.0 이상            1.00
```

색은 쓰지 않는다. `labelColor`에 알파만 준다 — 게이지와 같은 언어다.

### 문장

세션이 3개 이상 쌓인 칸들만 후보로 남기고, 그 후보 중 합계가 가장 큰 칸을
고른다. 동점이면 이른 요일, 그다음 이른 시간대.

> **구현 중 변경.** 처음 구현은 "합계가 가장 큰 칸을 먼저 고르고, 그 칸에만
> 3세션 문턱을 검사"하는 순서였다(`f103fa9`). 그런데 어쩌다 한 번 길게 집중한
> 칸은 세션 수가 적어도 합계는 클 수 있다 — 그 칸이 먼저 뽑히고 나서 문턱에
> 걸려 떨어지면, 정작 꾸준히 쌓아온 다른 칸이 있어도 앱이 침묵한다. 그래서
> 순서를 뒤집어 **후보를 먼저 거르고 그 안에서만 합계를 비교**하도록 고쳤다
> (`7fb3e45`, `Insight.best(totals:counts:sessionCount:)`).

**두 조건을 모두 넘겨야 문장을 낸다.** 창 안 세션이 10개 이상이고, 3세션 이상
쌓인 후보 칸이 하나 이상. 두 번 집중한 걸로 "화요일이 최적입니다"라고
단언하면 앱을 못 믿게 된다.

```
조건 충족   화요일 15시 전후에 가장 오래 집중했습니다.
           그 시간에 중요한 일을 두세요.
기록 부족   아직 기록이 적습니다.
기록 없음   아직 기록이 없습니다.
```

사실 한 줄, 제안 한 줄. 재촉하지 않는 톤을 지킨다.

### 이번 주 합계

월요일 시작, 현재 시간대 기준. `6시간 20분` 형태로 적는다.

## 언어

화면에 나가는 문자열은 전부 `Strings.swift` 테이블에 넣는다.

추가할 키: `history`, `historyBest`, `historyAdvice`, `historyNotEnough`,
`historyEmpty`, `weekTotal`, `durationHM`, `durationM`.

`history` 하나가 버튼 이름과 화면 제목을 겸한다. 같은 대상을 두 이름으로
부르지 않는다는 기존 규칙 그대로다.

`historyBest`는 `"%@ %d시 전후에 가장 오래 집중했습니다."` 형태다.
`L10n.s`가 `CVarArg`를 받으므로 `%@`에 요일 이름을 넘길 수 있다.

**예외 하나** — 요일 이름은 테이블에 넣지 않고 `DateFormatter.weekdaySymbols`
에서 가져온다. 21개 항목을 손으로 관리하는 대신 시스템이 주는 것을 쓴다.
선택된 언어로 `Locale`을 만들어 넘긴다. README 규칙에 대한 의도적 예외이므로
주석으로 남긴다.

## 검증

`Insight`가 순수 함수라 실제 코드를 그대로 태울 수 있다. `nextStep`,
`Stepping`과 같은 방식으로 단독 실행 파일을 만들어 확인한다.

| 확인할 것 | 방법 |
|---|---|
| 최다 칸 선택 | 특정 칸에 몰아넣은 가짜 세션 |
| 동점 처리 | 같은 합계 두 칸 → 이른 요일이 뽑히는지 |
| 침묵 기준 | 9세션, 그리고 최다 칸 2세션 → 문장 없음 |
| 빈 행 숨김 | 낮 시간대만 있는 데이터 → 새벽 행이 빠지는지 |
| 주 경계 | 일요일 23시와 월요일 00시가 다른 주로 갈리는지 |
| 시간대 이동 | 다른 오프셋으로 적힌 줄이 원래 시각에 남는지 |
| 8주 창 | 57일 전 세션이 빠지는지 |

`SessionLog`는 임시 경로에 쓰고 다시 읽어 왕복을 본다. 깨진 줄이 섞여도
나머지를 살려 읽는지 확인한다 — append 도중 종료되면 마지막 줄이 잘릴 수 있다.
